    示例中的 order_id 是数字，但契约要求字符串。这个错误不会被普通 JSON 格式化发现。

    两层验证，两个不同结论

    JSON 语法检查只回答“文本能否解析”；本页回答“解析后的数据是否符合你声明的字段规则”。例如 {"order_id":42} 是合法 JSON，但对要求字符串 ID 的接口仍然是无效数据。点击“载入订单示例”，你可以看到错误指向具体字段；把 42 改成 "42" 后重新验证。

    适用边界

    本站使用 Ajv 验证 2020-12 Schema，支持对象或布尔型顶层 Schema 和常见 format。校验在浏览器 Worker 内进行，超时会停止；不会从远端加载 $ref。即使结构通过，业务权限、金额、订单状态和重复执行风险仍需在可信服务端另行判断。输入不会提交到本站 API。

    不要把真实密钥或含个人信息的样例粘贴到共享截图和工单。Schema 中的正则也可能消耗大量计算资源，本页设置了输入和运行时限。

    规范与实现：JSON Schema 2020-12、Ajv 文档。完整上线检查见结构化输出验收指南。
