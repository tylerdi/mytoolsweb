JSON 格式化时，错误位置怎么找？

先确认它是不是合法 JSON，再看报错附近的分隔符和引号。格式化只改变排版，不会修复无效数据。

先用一段小数据验证流程

打开JSON 输出检查器，粘贴下面这段压缩数据并点击“检查 JSON”。结果会按两空格缩进，便于看清 user 对象和 roles 数组的边界。

{"user":{"name":"Lin","active":true},"roles":["editor","viewer"]}

这个工具在浏览器中调用 JSON.parse 验证输入，再用 JSON.stringify 输出。选择结果格式“压缩”会移除非必要空白，但保留数据结构。复制结果前，建议检查数字、布尔值和 null 是否仍是你预期的类型。

三种最常见的错误

1. 最后一个成员后面多了逗号

{"name":"Lin","active":true,}

对象末尾的逗号在 JavaScript 对象字面量中可以出现，但在 JSON 中不合法。删除 true 后面的逗号即可。数组最后一个元素后面的逗号也一样。

2. 把单引号当作字符串边界

{'name':'Lin'}

JSON 的键与字符串值必须使用双引号。改成 {"name":"Lin"}。如果字符串内部需要双引号，写成转义形式 \"。

3. 在字符串中直接换行

字符串里的换行要写为 \n，不能直接敲回车。例如 {"message":"第一行\n第二行"}。复制自日志或表格的内容尤其容易出现这个问题。

报错位置可能指向哪里？

浏览器的 JSON 错误信息通常报告“发现无法继续解析的位置”，不一定是最早写错的字符。先看报错点前面的逗号、冒号、引号和括号，再检查最近一层对象或数组是否闭合。长数据可以逐段保留字段、重复格式化，找出导致错误的那一段。

格式化不会删除敏感字段。真实接口响应中若含令牌、手机号或个人信息，请先脱敏，再复制结果到工单或聊天记录。

什么时候该用压缩？

排查问题时保留缩进更容易读；把 JSON 嵌入请求体或配置时，压缩能减少空白。压缩并不是加密，也不会让秘密字段变安全。若业务需要稳定的签名或哈希，还要注意键顺序和序列化规则，不能仅依赖页面上的压缩结果。
